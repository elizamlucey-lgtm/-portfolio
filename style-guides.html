Technical Writing Style Guide

Editorial principles for creating clear, consistent, accessible, and user-focused technical documentation.

Purpose

This style guide defines writing standards for technical documentation, developer content, product documentation, and user-facing content.

The goal is to create documentation that is clear, consistent, accessible, and easy for users to act on.

Voice & Tone

Voice

Documentation should be confident, helpful, direct, and respectful of the reader's time.

Tone

Tone should adapt to the user's situation while remaining professional and approachable.

  • Use clear and direct language.
  • Prefer active voice.
  • Avoid unnecessary jargon.
  • Explain unfamiliar technical concepts.
  • Focus on what the user needs to accomplish.

Plain Language

Write for understanding rather than complexity.

Before

Authentication credentials must be utilized in order to facilitate successful access to the administrative interface.

After

Use your credentials to sign in to the administrative interface.

Headings

Headings should describe the information that follows and allow users to scan the page quickly.

  • Use descriptive headings.
  • Keep headings concise.
  • Use sentence case.
  • Maintain a logical heading hierarchy.

Procedures

Use numbered steps when users need to complete actions in a specific sequence.

Example

  1. Sign in to the administrator console.
  2. Open Settings.
  3. Select Authentication.
  4. Configure the required authentication method.
  5. Select Save.

Each step should contain a clear action and should avoid combining unrelated actions whenever possible.

UI Terminology

Use interface labels exactly as they appear in the product.

Preferred Avoid
Select Save. Click the save button.
Open Settings. Go into the settings area.
Enter your username. Input your username.

Code Examples

Code examples should be complete enough for the reader to understand how the example works. 

curl https://api.example.com/users \
  -H "Authorization: Bearer YOUR_TOKEN"
  • Use syntax highlighting when supported.
  • Explain important parameters.
  • Never expose real credentials or secrets.
  • Use realistic but clearly fictional values.

Accessibility

Documentation should be accessible to users with different abilities, devices, and levels of technical experience.

  • Use descriptive link text.
  • Maintain logical heading structure.
  • Provide alternative text for meaningful images.
  • Do not rely on color alone to communicate meaning.
  • Use readable language and sufficient contrast.
  • Design content to work with assistive technologies.

AI-Assisted Documentation

AI can accelerate research, drafting, restructuring, and content analysis, but generated content must be reviewed by a qualified human.

  • Verify technical claims.
  • Validate code examples.
  • Protect confidential information.
  • Review terminology and product accuracy.
  • Check content against authoritative sources.
  • Maintain human editorial ownership.

Editorial Checklist

  • Is the user's goal clear?
  • Can the reader find the information quickly?
  • Are instructions actionable?
  • Is the terminology consistent?
  • Are technical claims accurate?
  • Are examples complete and safe?
  • Has accessibility been considered?
  • Has the content been reviewed?
